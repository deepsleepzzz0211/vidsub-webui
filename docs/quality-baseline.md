# 质量与回归基线（09 号票）

本文件记录**可复现的两条硬指标**：同一输入两次产出是否字节级一致，以及
英文字幕相对人工听写参考的字错率。

> 工单原本写的是「70 分钟课程（约 729 条字幕、总时长 4181.9 秒）」。经确认
> 改用下面这份 226 秒素材 —— 关键不是长度，而是**它有一份人工听写的官方
> 字幕**可以当参照。70 分钟那份只有官方**自动**字幕，而自动字幕自己就会
> 把 `GitHub` 写成 `gt gt`、把域名拆成 `dot com`，拿它当尺子量不准。

---

## 一、素材与参考

| | |
|---|---|
| 素材 | TED 演讲 *Keep your goals to yourself*（Derek Sivers），**226 秒** |
| 文件 | `r2t2-test/srt/video.final.mp4`（源视频，225.8s） |
| 参考字幕 | `r2t2-test/srt/dl/official.en.srt` —— **人工听写**，68 条，覆盖到 190.3s |
| 参考词数 | 523 |
| 机器 | AMD 7840HS / Radeon 780M / 纯 CPU，8 线程 |
| 模型 | R2T2 Q4_K_M（识别）+ Hy-MT2 1.8B Q4_K_M（翻译） |

素材尾部（190.3s 之后）还有一段赞助片头，参考字幕没有覆盖它。**比对时按参考
的覆盖范围裁剪**，否则那段转写会被算成插入错误，把字错率抬高。

## 二、结果

```
我们的 cue     55 条（比对 51 条，裁掉 4 条）    覆盖到 225.4s
参考 cue       68 条                             覆盖到 190.3s

参考 523 词    转写 522 词    比值 0.998   ← 先看这个
编辑距离 24    WER 4.59%      准确率 95.41%
```

**词数比 0.998 是前提**：比值接近 1.0 才说明两边覆盖同一段内容。比值不对时
下面的百分比没有意义 —— 之前踩过：滚动字幕没去重，词数 3 倍冗余，WER 虚高
到 69.98%，差点当成结论汇报。`tools/check_quality.py` 会把比值放在最前面并
自己判定可信度，不可信时以退出码 1 喊出来。

### 差异分类：真正听错的只占三分之一

| 类别 | 处数 | 影响词数 | 占差异 |
|---|---|---|---|
| 疑似真实听错 | 7 | 9 | 37.5% |
| 词形差异 | 6 | 7 | 29.2% |
| 分段边界重复/缺失 | 2 | 5 | 20.8% |
| 参考非语音标记 | 2 | 3 | 12.5% |

- **词形差异**：`afterward`/`afterwards`、`mouths`/`mouth`、`any time`/`anytime`
  （最后一个是分词边界不同，字母完全一样）
- **分段边界重复/缺失**：识别按自己的段边界切，边界词会被相邻两条各带一次
- **参考非语音标记**：官方把 `(Laughter)`/`(Applause)` 写进了正文，我们不该
  转写它们 —— 这属于工单点名的"官方字幕自身噪声"

结论：**约 62% 的"差异"不是识别错误**。只看一个 WER 总数会把它读成
"每 20 个字错 1 个"，实际听错率更低。

## 三、可复现性：一个真 bug 与它的根因

**修复前**：同一素材跑两遍，字幕**不一致** —— 两份只差 6 字节，且**差异全部
落在中文译文层，英文转写层字节完全一致**。所以只看英文或只看条数发现不了。

定位过程（每一步都排除了一个假设）：

| 假设 | 实验 | 结果 |
|---|---|---|
| 多线程浮点归约 | `-t 1` | ❌ 仍不稳定 —— 排除 |
| 随机种子 | `-s 0` | ❌ 仍不稳定 —— 排除 |
| **prompt 缓存** | `--no-cache-prompt` | ✅ **稳定** —— 命中 |
| 进程生命周期 | 跨进程重启各测一次 | 本来就稳定 |

**根因**：llama-server 默认开启 prompt 缓存。同一进程内的第二个请求复用上一
请求的 KV 前缀，**批处理路径就变了 → 浮点累加顺序变 → 偶尔 argmax 落在另一
个 token 上**。注意 `temperature` 已经是 0.0（贪心），所以这不是采样随机性，
关温度修不好它。跨重启之所以稳定，是因为每次都是完整 prefill。

**修法**：服务参数加 `--no-cache-prompt`（`runtime._common_args()`），并有
单测守着。代价可忽略：翻译的 prompt 只有几十个 token；识别的 prompt 每次
音频都不同，本来也命中不了缓存。

**修复后**：`tools/check_regression.py` 在 226 秒素材上跑两遍，退出码 0，
两份 SRT `cmp` 完全相同。

复验工具：`tools/check_determinism.py`（把上面那组对照实验固定下来，换模型或
换 llama.cpp 版本时一键重跑）。

## 四、怎么复现

```powershell
$env:VIDSUB_DATA_DIR="D:\vidsub"                 # 含 models/ 的目录，别含空格
$env:VIDSUB_LLAMA_SERVER="...\llama-server.exe"  # 路径可含空格
$env:VIDSUB_IDLE_TIMEOUT="0"                     # 别让空闲巡检中途回收模型

# 1. 字节级一致（会跑两遍，226 秒素材约 3 分钟）
python tools/check_regression.py <素材> --out .e2e-cache/quality-baseline

# 2. 字错率与差异分类
python tools/check_quality.py .e2e-cache/quality-baseline/1.srt <参考srt>

# 3. 翻译可复现性诊断（对照实验）
python tools/check_determinism.py
```

退出码约定：`check_regression.py` 的 3 = 权重不齐备（**不等于通过**）；
`check_quality.py` 的 1 = 词数比不可信（此时的 WER 不能当结论）。
